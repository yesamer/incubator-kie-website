We are happy to announce the release of **Apache KIE (Incubating) 10.3.0**. This release moves the platform to Spring Boot 4 and Quarkus 3.33, adds new rule-authoring capabilities to Drools, extends the workflow engine, and ships a long list of security and stability fixes.

<!-- truncate -->

## Highlights

- **One home for the engines.** Drools, OptaPlanner, Kogito Runtimes and Kogito Apps now live in a single repository.
- **New platform baseline.** Spring Boot 4 and Quarkus 3.33, on JDK 17 and 21.
- **Smarter rules.** A new `sequence()` DSL for ordered events, and rule attributes and CEP temporal operators in the RuleUnit DSL.
- **More flexible workflows.** Call sub-processes and send signals whose names are only known at runtime.
- **A new DRL Editor for VS Code**, with completion, navigation, diagnostics and formatting.
- **Simpler, faster releases.** Fully automated, locally runnable release scripts, and a new quarterly cadence.
- **Security.** Unsafe deserialization is closed, and many dependencies are upgraded.

## A New Repository Layout

With 10.3.0 we also changed how the source code is organized. Drools, OptaPlanner, Kogito Runtimes and Kogito Apps are now part of one single repository, **[`incubator-kie`](https://github.com/apache/incubator-kie)**, moved with its full Git history. The Apache KIE code is now spread across three repositories:

| Repository | Content |
| --- | --- |
| [`incubator-kie`](https://github.com/apache/incubator-kie) | The engines |
| [`incubator-kie-tools`](https://github.com/apache/incubator-kie-tools) | Tooling and front end |
| [`incubator-kie-examples`](https://github.com/apache/incubator-kie-examples) | Showcases |

Also with 10.3.0, **DashBuilder**, **SonataFlow** (Serverless Workflow support) and **YaRD** are no longer part of Apache KIE. They remain available in the `10.2.x` branches.

## A Quicker, More Predictable Release Cadence

Starting with 10.3.0, we revisited our release process to make it quicker and more minimal. We are now aiming to **release once a quarter**, with the next release targeted for **January 2027**.

### Platform Upgrades

| | 10.3.0 |
| --- | --- |
| **JDK** | 17 and 21 (officially supported) |
| **Quarkus** | `3.33.4` |
| **Spring Boot** | `4.1.1` (Spring Framework `7.0.9`) |

`incubator-kie-tools` moves to the same Spring Boot and Quarkus versions as the engines.

## Infrastructure Changes

Putting the engines in one repository was also a chance to rethink how we build, test and release. Most of this work is invisible to users, but it is what makes a faster release cadence possible.

- **Release procedures, much improved.** Releases are now fully automated, from the version update to the build, signing, staging and tagging. Only the community votes and the final publishing step stay manual, by design. The release jobs are plain, numbered scripts that can also be run locally on a developer machine, and Jenkins simply calls the same scripts. Releases are faster, simpler and easier to repeat.
- **Faster pull request checks.** CI runs on GitHub Actions. With more than 850 Maven modules in `incubator-kie`, building everything for every change would be too slow, so a pull request now builds only the modules it can affect and the modules that depend on them.
- **Partial builds on your machine.** `make dev` applies the same logic locally. It works out which modules your change touches, rebuilds any missing or outdated upstream modules, and builds only what is needed.

## Before You Upgrade

These changes can affect existing applications:

- **Spring Boot 3 is no longer supported.** Upgrade your application to Spring Boot 4.x. KIE continues to use Jackson 2 (as Quarkus requires it), with a correct Jackson 2 integration in all Spring Boot based modules.
- **Quarkus REST.** The `quarkus-resteasy` extension has been replaced by `quarkus-rest`. Review custom REST code and dependencies.
- **Default script language in BPMN.** On-entry and on-exit scripts that do not declare a `scriptFormat` are now interpreted as Java instead of MVEL. To keep MVEL, set `scriptFormat="http://www.mvel.org/2.0"` on the script. Script tasks already defaulted to Java. This change does not affect DMN or DRL.
- **User tasks.** All human task nodes in a BPMN process that share the same `TaskName` now share a single generated model (input, output and task model classes) and a single set of REST endpoints, instead of one per node. Regular work items keep their own model and endpoints. REST endpoints are generated by default for `Human Task` only; to enable them for another work item type, set `kogito.codegen.process.workitems.<work item name>.rest.enabled=true`. Task names that resolve to the same class name (for example `My Task` and `My-Task`) now fail the build with a clear error. Review any client code that calls the generated user task endpoints.
- **Interrupting event sub process.** Behavior is now aligned with BPMN 2.0 specification, section 13.4.4.
- **Sequential mode.** Beta node sharing is disabled, `@Propagation(IMMEDIATE)` is ignored, and `ForEachNodeInstance` with async nodes no longer falls back to sequential mode.
- **Process instance locking.** The `ProcessInstance` lock is now released at transaction commit, avoiding stale reads in multi-threaded scenarios.
- **Removed.** YaRD and Serverless Workflow (SonataFlow) support. DashBuilder is also no longer part of Apache KIE.

## What's New

### Drools

#### Rule Engine and DSL Enhancements
- **`sequence()` DSL and Phreak `SequenceNode`:** Rules can now match an ordered sequence of events. A new `sequence()` condition in the executable model DSL takes a list of steps, and each step can combine patterns with AND and OR. The rule fires only when the matching facts arrive in the declared order. The sequence is evaluated by a new Phreak node, `SequenceNode`.
- **RuleUnit DSL:** Rules defined with the RuleUnit DSL can now use rule attributes (`salience`, `noLoop`, `enabled`, `activationGroup`, `timer`, `calendars`, `dateEffective` and `dateExpires`), for example `rulesFactory.rule("HighSalience").salience(10)`. The DSL also supports STREAM event processing, enabled with `@EventProcessing(EventProcessingType.STREAM)` on the rule unit, and the CEP temporal operators `after`, `before`, `coincides`, `during`, `includes`, `meets`, `metby`, `overlaps`, `overlappedby`, `starts`, `startedby`, `finishes` and `finishedby`, for example `.after(5, 8, TimeUnit.SECONDS)`.
- **Declared enums** can now reference constants of other declared enums, for example `TARGET_PRESENT( Category.TARGET, "present" )`. A misspelled constant fails at compile time instead of at runtime.

```java
rule("seq-rule").build(
    sequence(
        pattern(toy).expr("ball", t -> t.getName().equals("ball")),
        pattern(relationship).expr("go", r -> r.getStart().equals("go"))),
    execute(() -> results.add("fired")));
```

#### Build and Tooling
- **YAML property retrieval:** Code generation now reads `application.yml` and `application.yaml` in addition to `application.properties`. Nested YAML keys are flattened to dotted property names.

### Workflow Engine
- **Dynamic process calling:** The `calledElement` of a call activity can now be an expression that is resolved from process variables when the activity runs, for example `calledElement="#{prefix + 'SubProcess'}"` or `calledElement="#{order.type}-process"`. If the expression cannot be resolved, or the resolved process does not exist, the call fails with an error.
- **Dynamic signals:** The name of a signal can be taken from a process variable, for example `<signal id="Signal_1" name="#{signalName}"/>`, so a process can wait for a signal whose name is only known at runtime.
- **Process variables:** A process can now be started with variables that it does not declare. They are kept with the process instance. You can also use `java.lang.Object` as the type of a process variable, and untyped collection variables are now supported in persistence.
- **REST work item handler:** You can limit the number of HTTP connections the handler keeps open per host with `kogito.workitem.rest.max-pool-size`. If you do not set it, the Vert.x default applies.
- **Data audit:** Data retrieved by the data-audit addons is now isolated by process id and version pair, so a query only returns data for the process and version it targets. The addons ship new database migration scripts (`V1.7.0`) that add the process id and version columns.
- **Flyway:** New `kie.flyway.out-of-order` property, `true` by default. Migrations whose version is lower than the latest applied version are now applied instead of ignored. Set it to `false` to keep the previous behavior.

### Tooling Updates

#### New DRL Editor for VS Code
10.3.0 introduces the **DRL Editor**, a VS Code extension for DRL (Drools Rule Language) files, powered by a dedicated Language Server. It lives in the `incubator-kie-tools` monorepo and is also bundled in the Kogito VS Code extension bundle. It requires Java 17 or later.

- **Editing:** Syntax highlighting, code completion, and inlay hints.
- **Navigation:** Go to definition, find references, rename, document symbols, type hierarchy, and folding ranges.
- **Diagnostics:** Syntax errors, lint checks with quick-fixes, and compile diagnostics produced on save by your project's own Drools engine.
- **Formatting:** *Format Document* and *Format Selection*, also available as a command-line tool.
- **Hover and code lens:** Hover tooltips for DRL and Java types, and reference counts on declared types.
- **File grouping:** Declare rule groups, or adopt the rule manifests your project already has.

#### BPMN Editor
The new BPMN Editor, introduced in 10.2.0, keeps maturing, and the *Classic to New* migration guide and an extensions and conventions guide are now available.

- **REST Service Call Task:** You can now configure REST service call tasks in the editor.
- **Sub-processes:** Sub-processes can be nested, and sequence flow labels can be moved by drag and drop.
- **Process properties:** A `processDuration` field was added to the global properties, and on-entry script formats are now persisted.
- **Events and data:** Event references on boundary events are updated when you rename or delete Messages, Errors, Escalations and Signals, and you can assign list type variables in multi-instance reusable sub-processes.
- **Backward compatibility:** Fixes for gateway outgoing edge conditions and for the DMN Business Rule Task.

#### DMN and Test Scenario Editors
- **DMN Editor:** Edge properties are displayed, and a crash on `Any`-typed lists is fixed.
- **Test Scenario Editor:** An error message is now displayed when you open a broken `.scesim` file.
- **VS Code:** A problem that kept the BPMN and DMN editors from loading in the VS Code extension is fixed.

#### Runtime Dev Tools and Consoles
- **jBPM Dev Console for Spring Boot:** A new Dev Console for Spring Boot applications, named `jbpm-spring-boot-dev-console`, with a *Spring Boot Compact Architecture* example.
- **Quarkus Dev UI:** Fixes for live reload, for starting a process instance with a `Date` input variable, and for forms that could not be opened from `jbpm-quarkus-dev`.
- **Management Console:** Fixes for "Update Variables" reporting and for a rendering block.
- **Data Index:** The web app now shows version information and links to the GraphQL UI.
- **Dev Deployments:** The `kube-apiserver-proxy` no longer crash-loops on arm64 clusters.

#### KIE Sandbox and Online Editors
- **Commit signing:** Git operations in workspaces now support commit signing.
- **DMN Runner:** The form now supports full namespace URIs for references within the same file.
- **CORS Proxy:** Optional TLS support, also configurable through the KIE Sandbox Helm chart.

#### Platform
- The UI was upgraded from **React 17 to React 18**.

## Security

This release fixes **CVE-2026-61401** (Apache Drools: bytecode injection and unsafe deserialization in protobuf session marshalling). The fix validates protobuf session deserialization and checks Java-serialized process variables against the Drools deserialization class allowlist. Classes not in the allowlist are rejected. If your application stores its own classes in process variables, add them to the `drools.serialization.allowedDeserializationClassPatterns` system property.

It also fixes a number of CVEs through dependency upgrades, including Jetty, Netty, Jackson, Micrometer, reactor-core, Apache MINA SSHD, the PostgreSQL JDBC driver, the MongoDB driver, and several JavaScript dependencies of the tooling. In addition, it fixes a path traversal issue in the dev-deployment upload service, adds missing security headers to `Extended Services` and CORS Proxy responses, and hardens log output against log forging. The full list is in the [changelog](https://github.com/apache/incubator-kie/blob/main/CHANGELOG.md).

## Fixes

More than 40 bugs were fixed, mostly in the rule engine (Phreak, subnetworks, accumulate, executable model), the DMN engine, and process code generation. See the changelog for the complete list.

## Community

Apache KIE is a community project, and this release shows it. The repository consolidation, the new DRL Editor, the BPMN Editor improvements and the many fixes came from contributors across the project. In `incubator-kie-tools` alone, close to 40 people contributed more than 200 commits since 10.2.0.

We also worked to make it easier to get involved:

- Both main repositories have a contribution guide, and `incubator-kie` also provides issue and pull request templates.
- With a single engines repository, there is one place to clone, build and send a pull request, instead of four.
- `make dev` shortens the edit-and-verify loop for new contributors.

Whether you want to report a bug, improve the docs, or fix something in the engines or the tooling, you are welcome.
